# AGENTS.md

## О проекте

Сервер отображения для проекта [livekit-transcript](https://github.com/mogafk/livekit-transcript) (транскрибатор созвонов
LiveKit). Транскрибатор через свой sink `http` шлёт события сессии POST-запросами сюда;
этот проект их принимает, держит в памяти и показывает реплики в браузере в реальном времени.

> **Статус:** работает всё описанное ниже: приём событий, правила протокола, REST и SSE,
> UI списка сессий и транскрипта, фейковый транскрибатор `scripts/replay.ts`. Проверено
> через `replay.ts`; с настоящим транскрибатором — ещё нет. Помеченное «(план)» — не
> сделано. При расхождении кода и файла — обновлять файл.

Две части:

- **server** — Node.js: ручка приёма событий от транскрибатора, сессии в памяти,
  API и поток обновлений для UI, раздача собранного UI.
- **ui** — Vue 3 + Vite + Pinia: список сессий и живой транскрипт выбранной сессии.

Основной сценарий:

1. `npm run dev` — сервер (`:8787`) и Vite (`:5173`, проксирует `/api` на сервер).
2. Транскрибатор запускается с конфигом `configs/livekit-http-sink.json`, в его `.env`
   `HTTP_SINK_URL=http://localhost:8787/api/ingest` и тот же `HTTP_SINK_TOKEN`, что у сервера.
3. Сервер создаёт сессию по первому пакету с новым `session.id`, применяет события.
4. Пользователь открывает UI, видит список сессий (идущие — сверху), открывает одну и
   смотрит, как появляются и уточняются реплики.

### Цели

- **Realtime:** реплика на экране ≤ ~100 мс после прихода пакета; interim-версии
  обновляются на месте.
- **Точное следование протоколу** [`docs/http-sink.md`](https://github.com/mogafk/livekit-transcript/blob/main/docs/http-sink.md) проекта livekit-transcript — это
  единственный источник правды о формате. Здесь его не дублировать; при изменении
  протокола правятся оба проекта.
- **Ответ транскрибатору быстрый и честный:** коды ответа управляют его повторами
  (см. «Ручка приёма»), поэтому ошибка кода сервера не должна выглядеть как «пакет
  неисправим».

### Не цели

- Управление транскрибатором (запуск/остановка из UI) — нет.
- Хранение сессий между перезапусками (БД, файлы) — нет и не будет.
- Редактирование транскриптов — нет. Экспорт — только JSON из UI (экспорт `.txt` — план).
- Авторизация в UI, многопользовательность — нет: записи не хранятся долго.
- Деплой — нет: есть только `Dockerfile` для запуска в контейнере.

## Ручка приёма — `POST /api/ingest`

Протокол — [`docs/http-sink.md`](https://github.com/mogafk/livekit-transcript/blob/main/docs/http-sink.md) проекта livekit-transcript, версия 1. Что важно для сервера:

- **Авторизация:** `Authorization: Bearer <токен>` проверяется в `onRequest`, до чтения
  тела. Сравнение — `timingSafeEqual` sha256 от заголовка и от ожидаемого значения:
  постоянное время, и длина токена тоже не утекает. Токен — `HTTP_SINK_TOKEN`; без него
  (или короче 16 символов) сервер не стартует, код выхода 2.
- **Коды ответа** (транскрибатор их интерпретирует):

  | Ситуация                                       | Код                                         |
  | ---------------------------------------------- | ------------------------------------------- |
  | пакет принят (в том числе целиком из дублей)   | `204`                                       |
  | нет / неверный токен (даже при битом теле)     | `401` — транскрибатор повторит тот же пакет |
  | тело не JSON, не проходит схему, `version` ≠ 1 | `400` — транскрибатор **отбросит** пакет    |
  | внутренняя ошибка сервера                      | `500` — транскрибатор повторит              |

  `400` — только когда пакет действительно неисправим. Любая ошибка нашего кода — `5xx`
  (так Fastify отвечает на исключение по умолчанию), иначе события теряются.

- **Валидация** (`protocol.ts`): весь пакет проверяется до применения — битое событие
  в середине даёт `400`, и ничего из пакета не применяется. Незнакомые поля отбрасываются
  (zod по умолчанию), незнакомые `type` становятся событием `unknown`: `seq` продвигается,
  больше ничего. Обязательны только поля известных событий.
- **Сессия:** создаётся по первому пакету с новым `session.id`, не дожидаясь
  `session_started`. `session.name` — имя комнаты; у одной комнаты может быть
  несколько сессий.
- **Дубли:** у сессии хранится `lastSeq`; события с `seq <= lastSeq` пропускаются.
  Пропуски `seq` — норма, не ошибка.
- **Реплики:** ключ — `segment_id`. Новая версия заменяет старую; после `is_final: true`
  всё по этому `segment_id` игнорируется (множество `finalized`). Финал с пустым `text` —
  реплика удаляется (и не создаётся, если её не было). Порядок — по `segment.start`,
  при равенстве — по `segment_id`.
- **Спикеры:** `speaker_joined` / `speaker_left` ведут список участников и их статус
  «в комнате»; повторный `joined` с тем же `id` — тот же спикер. `segment` от
  неизвестного спикера (его `joined` был в потерянном пакете или до перезапуска
  сервера) добавляет спикера по `speaker_id` / `speaker_name`.
- **Статус сессии:** `live` → `ended` по `session_ended`. Без пакетов дольше
  `SESSION_IDLE_TIMEOUT_S` (по умолчанию 300) — `idle`, в UI «нет событий»; проверка —
  таймером раз в 5 с. Это не обязательно «транскрибатор упал»: в протоколе нет heartbeat,
  и тихий созвон тоже молчит. Новый пакет возвращает `idle` в `live`; `ended` не меняется.
- Применение пакета атомарно относительно UI: подписчики получают изменения после
  обработки всего пакета, последним — обновлённую сводку сессии.

Для проверки без транскрибатора — `npm run replay` (`scripts/replay.ts`): созвон двух
спикеров с interim-версиями, пропусками `seq`, повтором пакета, пустым финалом и
переподключением спикера; `--speed 4` — быстрее, `--no-end` — без `session_ended`.
Эталон поведения — отладочный сервер [`scripts/http_sink_server.py`](https://github.com/mogafk/livekit-transcript/blob/main/scripts/http_sink_server.py) в livekit-transcript.

## Сервер → UI

Типы сообщений — `shared/src/messages.ts`.

- `GET /api/sessions` — список `SessionSummary`: `id`, `name`, `startedAt`, `status`
  (`live` / `ended` / `idle`), `lastEventAt` (когда сервер получил последний пакет),
  `speakerCount`, `segmentCount`.
- `GET /api/sessions/:id` — `SessionDetail`: сводка, спикеры, реплики по порядку; `404`,
  если сессии нет.
- `GET /api/sessions/:id/events` — **SSE**: первым сообщением `snapshot`, затем изменения
  `session` / `speaker` / `segment` / `segment_removed`. `GET /api/sessions/events` —
  SSE списка: `snapshot`, затем `session`. Каждые 15 с — комментарий `: ping`.
- SSE, а не WebSocket: поток односторонний, `EventSource` сам переподключается после
  сетевой ошибки. На не-200 (`404` — сессии нет после перезапуска сервера) `EventSource`
  сдаётся — UI переподключается сам раз в 3 с (`ui/src/api/stream.ts`). Каждое
  подключение начинается со снимка — счётчики версий не нужны.
- Формат сообщений сервер → UI — свой (camelCase), не формат протокола
  транскрибатора: UI не знает о `seq`, дублях и правилах финализации.

## Хранение

- Только в памяти (`server/src/store.ts`), без БД и файлов — и в планах тоже. Сессии
  не переживают перезапуск сервера и не удаляются, пока он работает.
- После перезапуска транскрибатор продолжит слать события идущей сессии, и она
  появится заново с этого места (без ранних реплик и спикеров, зашедших до перезапуска —
  спикер добавляется и по первому `segment`).

## UI

- Язык интерфейса — русский; тексты прямо в шаблонах, без i18n.
- Маршруты (`vue-router`, history mode): `/` — список сессий, `/sessions/:id` — транскрипт.
  Сервер отдаёт `index.html` на любой `GET` вне `/api/`.
- Pinia-сторы (setup-стиль): `sessions` (список + его SSE), `transcript` (открытая сессия +
  её SSE). Подписка открывается при входе на страницу и закрывается при уходе.
- Реплики и спикеры в сторе — `Map` по id, сортированный список — `computed`.
- Реплика: время начала (`чч:мм:сс`, локальное), имя спикера, текст. Interim — курсивом,
  приглушённым цветом и с «…». Цвет спикера — оттенок от хеша `speaker_id`, светлота —
  из темы (`--speaker-l`).
- Автопрокрутка вниз, пока пользователь у низа страницы (48 px); прокрутил вверх —
  кнопка «К последним репликам».
- Видны статус сессии («идёт / нет событий / завершена»), вышедшие спикеры (зачёркнуты)
  и потеря связи с сервером (полоса сверху).
- Светлая и тёмная тема — по `prefers-color-scheme`, цвета — CSS-переменные в `style.css`.

### Экспорт и открытие JSON

- На странице сессии «Экспорт JSON» скачивает то, что сейчас на экране: `SessionDetail` +
  `format: "livekit-transcript-ui/session"`, `version: 1`, `exportedAt`. Собирается в браузере,
  сервер не участвует. Имя файла — `<комната>_<ГГГГ-ММ-ДД_чч-мм>.json` (локальное время начала).
- На главной «Открыть JSON» читает такой файл (`parseExport` проверяет формат и поля) и
  показывает его на `/file` тем же `SessionView`, без SSE. Файл живёт только в сторе
  `transcript`: на сервер не уходит, после перезагрузки страницы `/file` уводит на `/`.
- Формат файла — свой, не протокол транскрибатора. Несовместимое изменение формата —
  новая `version`; старые файлы при этом должны либо читаться, либо давать понятную ошибку.

## Стек

- **Node.js 24**, **TypeScript** везде (strict, `noUncheckedIndexedAccess`), ES modules
- **npm workspaces** — монорепо: `shared`, `server`, `ui`
- **server:** **Fastify 5** (логи — встроенный pino, логи запросов выключены),
  **@fastify/static**, **zod 4**; без сборки: `npm start` и Docker — `node src/index.ts` (Node 24 сам отбрасывает типы,
  поэтому `erasableSyntaxOnly`: без enum, namespace и `constructor(private x)`), `dev` — `tsx watch`
- **ui:** **Vue 3** (`<script setup lang="ts">`), **Vite**, **Pinia**, **vue-router**; **vue-tsc**
- **shared:** только типы (`import type`), без кода и сборки
- **Vitest** — тесты сервера и `ui/src/export-file.ts`; **ESLint** + **Prettier**
- Импорты в server и scripts — с расширением `.ts`, в ui — без (так принято у Vite).

## Конфигурация (переменные окружения сервера, `.env`)

`.env` — в корне репозитория (его же читают Vite для порта прокси и `replay.ts`),
в `.gitignore`; шаблон — `.env.example`.

| Переменная               | Смысл                                                               | По умолчанию |
| ------------------------ | ------------------------------------------------------------------- | ------------ |
| `HTTP_SINK_TOKEN`        | токен транскрибатора, то же значение, что в его `.env`              | обязательна  |
| `HOST`                   | адрес; в Docker-образе — `0.0.0.0`, в `.env` для Docker не задавать | `127.0.0.1`  |
| `PORT`                   | порт                                                                | `8787`       |
| `SESSION_IDLE_TIMEOUT_S` | через сколько без пакетов сессия `idle`                             | `300`        |

Токен: `python -c "import secrets; print(secrets.token_urlsafe(32))"`.

Транскрибатор шлёт по `http://` только на `localhost`; если сервер не на той же
машине — нужен HTTPS (TLS-терминация в reverse proxy, например Caddy). (план)

Правила (проверять при ревью):

- `apply.ts` — без I/O и таймеров: меняет состояние сессии на месте и возвращает
  изменения для UI. Все правила протокола живут и тестируются здесь.
- `ui` не импортирует `server`, `server` не импортирует `ui`; общее — только типы `shared`.
- Схема протокола живёт только в `server/src/protocol.ts`.

## Проверка

- `npm test` — тесты `apply.ts`: interim → final, события после финала, дубли и пропуски
  `seq`, пустой финал с interim и без, спикеры и переподключение, спикер без `joined`,
  статусы, незнакомые типы и поля, сортировка. Тесты `ingest`: `204` / `401` / `400`,
  атомарность пакета, сравнение токена; `idle` в store.
- Сквозная проверка без транскрибатора: `npm run dev` + `npm run replay`.
- С транскрибатором: источник `wav` (`realtime: true`) и sink `http` на этот сервер —
  реплики появляются в UI во время проигрывания. (план: ещё не проверено)
